## 1. MRD 목적과 원칙

- **제품 포지셔닝:** 일회성 컨설팅 대행이 아닌, 표준화된 셀프서비스 구독형 규제 운영 플랫폼. (출처: shared-facts.md)
- 고객별 문서 대행 서비스가 아니라 **표준화된 셀프서비스 구독형 규제 운영 플랫폼**을 만들기 위한 시장 요구만 채택
- 의료기기 규제 특성상 **데이터 주권, 추적성, 검토 가능성, 근거 링크**가 모든 요구사항의 상위 전제
- AI는 규제 전문가의 판단을 대체하지 않고 **반복 검토·근거 검색·초안 생성·불일치 탐지**를 보조

## 2. 시장 배경과 기회

의료기기 제조사는 제품 안전성, 성능, 라벨링, 품질시스템, 사이버보안, 위험관리 증적을 지속적으로 관리해야 한다.  
이러한 구조는 국가별 공개 규제 지식과 제조사 내부 문서 간 연결성을 요구한다.

| 시장 요구 | 근거/배경 | 제품 요구로의 전환 |
|---------|---------|---------------|
| 국가별 규제 지식 업데이트 추적 | FDA/MFDS/EU MDR 등 공개 문서가 지속적으로 개정 | 클라우드 지식 수집기, 변경 감지, 지식팩 버전 관리 |
| 내부 문서 보안 | 기술문서·설계치·임상 원자료는 제조사 핵심 자산 | 고객사 로컬 런타임에서 민감 데이터 처리 |
| 문서 간 일관성 | IFU, SRS, RMS, 시험성적서가 서로 불일치하면 보완 리스크 증가 | Traceability Graph와 Consistency Guardrail |
| 근거 기반 검토 | 심사/감사 대응에는 문서 변경 이력과 근거 링크가 중요 | Audit Log, Evidence Link, Export 기능 |
| 셀프서비스 도입 | 스타트업은 RA 전문 인력 부족, 컨설팅 의존도 높음 | 템플릿, 보정 UI, 역할별 검토 큐 |

## 6. MVP 범위와 제외 범위

| 구분 | MVP 포함 | MVP 제외/후순위 |
|------|---------|-------------|
| 규제 소스 | FDA 주요 가이던스/개요, MFDS 의료기기 규정 목록, EU MDR 핵심 문서 | 모든 국가/언어/품목군 자동 커버리지 |
| 문서 포맷 | DOCX, XLSX, 텍스트 기반 PDF 일부 | 스캔 품질 낮은 이미지 PDF 완전 자동 OCR |
| 문서 유형 | IFU, SRS, 위험관리 파일, 시험성적서 요약 | 임상 원자료, 원본 소스코드, CAD/회로도 분석 |
| AI 기능 | 근거 기반 검색, 초안/요약, 불일치 후보 제시 | 규제 승인 가능성 자동 판정 |
| 배포 | 단일 고객사 로컬 Docker, 클라우드 지식팩 | 대규모 멀티사이트 복제/DR 자동화 |
| 서비스 | 표준 온보딩/체크리스트 | 무제한 문서 양식 커스터마이징 대행 |

**MVP 성공 조건:**
- 초기 고객은 표준 스키마 도입과 책임자 검토 프로세스를 수용해야 한다
- 핵심 지표는 "누락/불일치 탐지와 근거 링크 보존"에 둔다
- 규제 변경 영향도는 자동 확정이 아니라 검토 큐와 근거 기반 초안으로 제공한다

## 8. 고객 여정과 사용 시나리오

```
1. 고객 관리자 → 로컬 Docker 패키지 설치 + outbound endpoint 등록
        ↓
2. RA/QA 담당자 → IFU, SRS, 위험관리 보고서, 시험성적서 업로드
        ↓
3. Dynamic Parser → Unified Schema 필드 매핑 + confidence 표시
        ↓
4. Consistency Guardrail → 위험통제-요구사항-경고문-검증증적 연결성 검사
        ↓
5. 규제 변경 이벤트 → 관련 제품군/문서 필드에 영향도 큐 생성
        ↓
6. 책임자 → AI 제안 + 근거 링크 검토 → 승인/반려/수정 → 감사로그 보관
        ↓
7. 산출물 내보내기 → 제출 준비용 요약, 추적성 매트릭스, 보완 대응 초안
```

## 10. 고객 검증 계획

> **현황:** 파일럿 진행 전 단계. 실제 인터뷰/검증 데이터는 파일럿 완료 후 추가 예정.  
> **방침:** 허위 데이터 미포함. 검증 설계와 목표 지표만 구조화.

### 검증 목표 및 계획

| 검증 단계 | 대상 | 방법 | 목표 지표 |
|---------|------|------|---------|
| **인터뷰 (파일럿 전)** | RA 매니저, QA 리드 5~10명 | 반구조화 인터뷰 (30~45분) | 핵심 페인포인트 확인, 도입 의향 파악 |
| **파일럿 0.1 (내부)** | 내부 문서 샘플 20세트 | 파싱 정확도·속도 측정 | 핵심 필드 70%+ 추출 |
| **파일럿 0.5 (외부)** | 의료기기 스타트업 1~2곳 | 실제 문서 사용성 테스트 | 검토 시간 단축 측정 가능 여부 확인 |
| **Beta 검증** | 유료 파일럿 전환 검토 | NPS·재계약 의향 | NPS 40+ 목표, 재계약 의향 60%+ |

### 파일럿 성공 지표 (목표, 측정 예정)

| 지표 | 측정 기준 | 파일럿 전후 비교 방법 |
|------|---------|-----------------|
| 핵심 필드 파싱 정확도 | 정답 세트 대비 | 수동 라벨링 비교 |
| 문서 검토 시간 단축 | Before/After 시간 측정 | 파일럿 참여사 제공 수치 |
