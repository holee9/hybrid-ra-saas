## 1. plan_summary

Replace the `StubParserService` stub edge (left by SPEC-API-001) with a real 3-stage extraction
engine in a new `parser_engine/` package, driven strictly TDD (RED→GREEN→REFACTOR) across 12 tasks.

Approach:
- **Bottom-up dependency order**: pure data models + math first (T-001, T-002), then I/O readers
  (T-003, T-004), then the three stages (T-005–T-007), then orchestration (T-008), then the
  `parser.py` delegation seam (T-009), then the API surface (T-010), then quality gates (T-011, T-012).
- **Every external edge is injected** (spaCy model loader, Ollama HTTP client, sentence-transformers
  embedder) so unit tests run with fakes and zero network/GPU. Real-dependency paths are
  `@pytest.mark.integration` and auto-SKIP locally.
- **Backward compatibility is a hard constraint**: `ParserService`, `StubParserService`, and the
  existing `ParseResult` dataclass must keep working; `ParseJobResponse` stays wire-compatible.
- spaCy absence (B1) is absorbed by lazy import + mockable loader, so the package never hard-fails.

Total new files: 7 in `parser_engine/` + schema additions + 1 router method + ~9 test files.

## 2. architecture_decisions

| ID | Decision | Rationale | Trade-off accepted |
|----|----------|-----------|--------------------|
| AD-1 | `parser_engine` is a **package**, `ParserEngine` is the only public export via `__init__.py`. Stage modules are internal. | Single seam for `parser.py` to delegate to; keeps stage details encapsulated. | Slightly more boilerplate than flat module. |
| AD-2 | **Dependency injection for all external edges.** `ParserEngine.__init__` accepts optional `ner_model_loader`, `llm_client`, `embedder` callables/objects; defaults lazily construct real ones. | Enables unit tests with fakes (no spaCy/Ollama/GPU). Directly satisfies REQ-006/007 testability + B1/B3. | Constructor surface larger; documented. |
| AD-3 | **Stages are pure functions over `(text, fields_needed) -> dict[field, FieldExtraction]`.** Orchestration owns the early-exit/fallback loop. | Scenario 8 (early termination) and 4/5 (thresholds) testable without touching stage internals. | Stage cannot short-circuit the loop itself; orchestrator decides. |
| AD-4 | **`confidence.py` holds the weighted formula + threshold constants** (`CORRECTION_UI_THRESHOLD=0.85`, `REJECT_THRESHOLD=0.50`), env-overridable via `app.config`. | REQ-002 single source of truth; thresholds tunable without code change. | Must read config at call time, not import time, to honor overrides. |
| AD-5 | **`llm_fallback.py` injects an `httpx.AsyncClient` and reads Ollama base URL from config** (`OLLAMA_ENDPOINT`). A hard guard rejects any non-localhost/non-configured host. | REQ-007 data sovereignty enforced in code, not just tests. Scenario 7 asserts guard + zero external calls. | Guard logic must allow Docker-internal host (`http://ollama:11434`) seen in conftest. |
| AD-6 | **spaCy lazily imported inside `spacy_ner.py` behind a loader**; ImportError → stage returns empty extractions (graceful degrade), logged once. | B1: package must import and run end-to-end even with spaCy absent (rule+LLM still work). | spaCy stage is a no-op until model+lib present; covered by integration test only. |
| AD-7 | **`parser.py` keeps `ParseResult` and `StubParserService`**; new `EngineParserService(ParserService)` wraps `ParserEngine` and maps `ParsedFields → ParseResult` for the existing contract. | Constraint: StubParserService preserved, existing `POST /parse` path unchanged structurally. | Two result shapes coexist (`ParseResult` legacy + `ParsedFields` rich); mapping function bridges. |
| AD-8 | **`PATCH /parse/{job_id}/corrections` reuses the audit-hash + state pattern** already in `routers/documents.py` (`compute_correction_hashes`) and `core/state_machine.py`. | Consistency with existing SPEC-API-001 correction endpoint; no duplicate hashing logic. | Must confirm `ParsedFields` is persisted in `ParseJob.result_json` to reload/mutate. |
| AD-9 | **`ParsedFields` is stored in `ParseJob.result_json`** as serialized dict; correction endpoint reloads, mutates, recomputes, re-persists. | REQ-008 needs durable field state for PATCH. `result_json` JSON column already exists on the model. | `ParseJobResponse` must coexist with richer `ParsedFields` payload (back-compat via optional fields). |

### Schema evolution (ParseJobResponse → ParsedFields)
- `ParsedFields` is **additive**. `ParseJobResponse` keeps its current 5 optional fields for
  back-compat. New responses MAY include a `parsed_fields: ParsedFields | None` field.
- The `POST /parse` job, on completion, writes `ParsedFields.model_dump()` into
  `ParseJob.result_json["parsed_fields"]`; the legacy `field_candidates`/`confidence`/`required_missing`
  keys are also populated by the `ParsedFields → ParseResult` mapper (AD-7) so `GET /parse/jobs/{id}`
  is unchanged.

## 5. ci_test_strategy (unit vs integration)

(`_docker_available` → skip). pytest markers: only `integration` registered. `asyncio_mode=auto`.

## 7. interface_contracts

### ParserService ↔ ParserEngine
```
ParserEngine.parse(file_bytes: bytes, doc_type: str) -> ParsedFields        # rich, new
EngineParserService(ParserService).parse(file_bytes, doc_type) -> ParseResult  # legacy contract
    └─ internally: ParsedFields = await ParserEngine.parse(...)
       return parsed_fields_to_parse_result(ParsedFields)  # AD-7 mapper
StubParserService(ParserService)  # UNCHANGED — still returns configured ParseResult
```
- `ParserService.parse` async signature preserved exactly: `(self, file_bytes, doc_type) -> ParseResult`.
- `ParseResult` dataclass (confidence, field_candidates, required_missing) UNCHANGED.

### Mapper `parsed_fields_to_parse_result(pf: ParsedFields) -> ParseResult`
- `confidence` = `pf.overall_confidence`
- `field_candidates` = `{name: fe.value for name, fe in pf fields}`
- `required_missing` = required field names where `fe.value is None or fe.needs_correction`

### Schema evolution (ParseJobResponse)
- UNCHANGED fields: `job_id, status, field_candidates?, confidence?, required_missing?`
- ADDED (optional, back-compat): `parsed_fields: ParsedFields | None = None`
- `GET /parse/jobs/{id}` continues to populate legacy fields via the mapper; MAY also surface
  `parsed_fields` from `result_json["parsed_fields"]`.

### Persistence contract
- `ParseJob.result_json` (existing JSON column) stores:
  `{"parsed_fields": <ParsedFields.model_dump()>, "field_candidates": ..., "confidence": ..., "required_missing": ...}`
- `PATCH /parse/{job_id}/corrections` reads `result_json["parsed_fields"]`, mutates, recomputes,
  writes back. Tenant guard identical to existing `GET /parse/jobs/{job_id}`.

### Dependency injection (deps.py)
- Add `get_parser() -> ParserService` returning `EngineParserService(ParserEngine(...))`.
- `ParserEngine.__init__(*, ner_model_loader=None, llm_client=None, embedder=None, config=...)`.
