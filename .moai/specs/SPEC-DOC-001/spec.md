## 1. 실측 현황 (DOCX 직접 분석 결과)

> HTML 제안서만 분석한 v1과 달리, DOCX 원문 XML을 직접 파싱하여 실제 완성도를 측정했습니다.

- ✓ 릴리즈 우선순위 4단계 (Go/No-Go 기준 포함)

## 4. 실행 계획 (2-Phase)

### Phase 1: BizPlan + MRD 85% 확보 (Priority High)

**병렬 실행 가능:**

**Stream A — BizPlan 팀 & 재무 (T01 + T02 + T03):**
```
T01: 팀 섹션 추가
  - 창업자 프로필 (역할, 의료기기/RA/SaaS 관련 경험)
  - 핵심 채용 계획 (NLP 엔지니어, DevOps, RA 자문)
  - 어드바이저 2~3명 (의료기기/규제 전문가)

T02: TAM/SAM/SOM 추가
  - TAM: 글로벌 의료기기 RA 서비스 시장 ($2~4B 추정)
  - SAM: RA 플랫폼 SaaS 가능 시장 ($500M~1B)
  - SOM: Y1~Y3 공략 가능 (한국+미국 스타트업/중견, $50~100M)

T03: 재무 시나리오 숫자 추가
  - 섹션 8 보완: Core 10/30/50개 × $299/월 기준 ARR 표
  - Advanced 2/5/10개 × $12,000/년 기준 ARR 표
  - 인건비 가정: 팀 3~5명 기준 월 고정비
```

**Stream B — BizPlan 경쟁사 & MRD 시장 규모 (T04 + T05):**
```
T04: 경쟁사 명칭 분석 추가 (섹션 9 또는 별도 섹션)
  - Veeva Vault Quality (대형 QMS, 도입 비용 높음)
  - Sparta Systems (TrackWise, 제약/의료기기 특화)
  - MasterControl (QMS, 작은 기업 대상)
  - 범용 SaaS (Notion, Confluence + 수동 관리)
  - 기존 RA 컨설팅 (1회성, 지식 내재화 어려움)
  → 본 제품 포지션: 경량 하이브리드, 데이터 주권, 로컬 배포

T05: MRD 시장 규모 추가 (섹션 2 보완)
  - 동일한 TAM/SAM/SOM을 MRD 시장 배경 섹션에 삽입
  - 의료기기 세그먼트별 규제 복잡도와 TAM 분해
```

**Stream C — MRD 보완 (T06 + T07):**
```
T06: 경쟁사 명칭 매트릭스 (섹션 9 업데이트)
  - 현재 4가지 유형에 구체적 벤더명 추가

T07: JTBD → 사용자 스토리 변환
  - 기존 페르소나 3~4종을 "As a [페르소나], I want [목표], So that [결과]" 형식으로 보완
  - 15개 이상 스토리, MoSCoW 우선순위 태그
```

### Phase 2: PRD 90%+ 달성 (Optional, 선택적 진행)

**T09 — UI/UX 와이어프레임:**
- 대시보드, 문서 업로드, 검토 큐, RAG 검색, 설정, 감사로그 8개 주요 화면
- Figma 또는 ASCII/Mermaid 다이어그램으로 표현 가능

**T10 — 파서 NLP 상세 명세 (FR-201 보완):**
- X-ray IFU 핵심 필드 10~15개 정의
- 신뢰도 계산 공식 (필수 필드 완성도 + 규칙 매칭 + 시멘틱 스코어)
- spaCy NER vs LLM 폴백 선택 근거

**T11 — Docker Compose 파일:**
- app, postgres, minio, ollama 4개 서비스
- 환경변수 목록 (CUSTOMER_ID, LOCAL_GPU, KNOWLEDGE_PACK_VERSION 등)
- 헬스체크 설정

**T12 — OpenAPI 완전 명세:**
- 기존 6개 엔드포인트에 요청/응답 JSON Schema 추가
- 인증 헤더 명세 (Bearer JWT + tenant_id)
- 오류 코드 목록
