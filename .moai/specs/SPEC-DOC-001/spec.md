## 0. v2 → v3 개정 사유 (교차검증 결과)

v2는 HTML/DOCX "섹션 존재 여부"만으로 측정했고, GAP 플레이스홀더 섹션을 완성도로 과대 반영했다. v3는 4개 독립 에이전트가 동일 가중 루브릭으로 `docs/*.md` 본문을 실측한 결과를 반영한다.

| 문서 | v2 주장 | v3 실측 (가중 루브릭) | 정정 폭 | 정정 근거 |
|------|--------|---------------------|--------|---------|
| BizPlan | 78~82% | **68.0%** | -10~14pp | T01/T02/T03 본문은 `[GAP-Txx]` 플레이스홀더만 존재(0.25점), T04 벤더명 나열만(0.40점) |
| MRD | 80~85% | **74.0%** | -6~11pp | T05~T08 전부 플레이스홀더, 4개 항목 합산 -14.5pp |
| PRD | 85~88% | **81.4%** | -4~7pp | API 차원 0.50(구현 차단), 로컬런타임 0.72(docker-compose 없음) |
| 문서 간 일관성 | (측정 안 함) | **68/100** | 신규 | 아키텍처 명칭 충돌, 추적성 매트릭스 부재 등 9건 |

**DOCX 원문 대조 결과:** `docs/*.md`는 DOCX의 충실한 상위집합이며 콘텐츠 손실 없음. GAP을 명시적으로 라벨링한 것은 긍정적. 즉 완성도 부족은 "누락"이지 "퇴행"이 아니다.

## 4. Track C — 제품 구현 로드맵 (코드 0% → SPEC 씨앗 착수)

본 레포는 기획 문서만 있고 코드가 없다. PRD의 구현 준비도를 평가하여 후속 구현 SPEC 씨앗을 정의한다.

### 4.1 구현 준비도 매트릭스

| 단계 | 준비도 | 최대 차단 갭 | 권장 SPEC 씨앗 |
|------|-------|-----------|-------------|
| Phase 1 Infra | 중 (60%) | Terraform이 S3/SQS/SNS만, RDS/pgvector·Lambda·IAM 미정의 | **SPEC-INFRA-001**: Cloud Control Plane 전체 Terraform(RDS Aurora+pgvector, ECS Fargate 크롤러, IAM, API Gateway, CI/CD) |
| Phase 2 Logic | 낮음 (45%) | docker-compose 없음, 파서 NLP 명세 없음, 골든셋 미정의 | **SPEC-PARSER-001**: Dynamic Parser+Guardrail(IFU 필드 15개, confidence 알고리즘, 폴백 트리, 골든셋 구성) |
| Phase 3 Product | 낮음 (35%) | 와이어프레임·OpenAPI 스키마 없음 | **SPEC-API-001**: 로컬 런타임 OpenAPI 3.1 완전 명세 + docker-compose.yml + 인증/오류코드 |
| Phase 4 Scale | 매우 낮음 (20%) | 지식팩 버전관리·테넌트 격리 설계 없음 | **SPEC-KNOWLEDGEPACK-001**: manifest 스키마, 증분 패치 포맷, 테넌트 격리 모델, 품목 확장 메타데이터 |

### 4.2 의존성 및 착수 순서

```
Track A·B (문서 85%+ 일관성) ──┐
                              ├─→ SPEC-API-001 (OpenAPI+compose) ─┐
SPEC-INFRA-001 (Terraform) ───┘                                  ├─→ SPEC-KNOWLEDGEPACK-001
SPEC-PARSER-001 (NLP 명세) ──────────────────────────────────────┘
```

**착수 권장 순서:** Track A·B 완료(문서 신뢰 확보) → SPEC-API-001 + SPEC-INFRA-001 병렬 → SPEC-PARSER-001 → SPEC-KNOWLEDGEPACK-001. 각 씨앗은 별도 `/moai plan`으로 독립 SPEC화한다 (본 SPEC 범위는 "착수 정의"까지).

## 5. 85% "유지" 메커니즘 (사용자 핵심 요구)

달성은 1회성이나 유지는 지속적이다. 다음 메커니즘으로 85% 이탈을 방지한다.

1. **단일 출처(`docs/shared-facts.md`)**: 가격·지표·품목·포지셔닝을 1곳에서 관리 → 문서 간 드리프트 구조적 차단 (C03).
2. **분기 재채점**: 1절 가중 루브릭으로 분기 1회 전 문서 재채점, 결과를 본 SPEC §1에 기록. 어느 문서든 85% 미만 시 해당 갭 작업 재개.
3. **기준일 필드**: 재무·시장·경쟁 섹션에 `기준일` 명시. 인용 출처 만료(2년+) 시 갱신 트리거.
4. **유지 고위험 섹션 워치리스트**: BizPlan §8 재무·§10 TAM·§11 경쟁 / MRD §2 시장규모·§10 고객검증 / PRD §9 API·§11 파서 — 변경 빈도 높음, 우선 점검.
5. **일관성 체크리스트(§7) 자동 점검**: 단일 출처 값과 각 문서 값 일치 여부를 Run/Sync 단계에서 확인.
